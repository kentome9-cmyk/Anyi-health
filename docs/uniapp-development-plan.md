# 门店端 uni-app 开发计划

## 1. 项目目标

在不影响现有系统使用的前提下，新增 uni-app 门店端，并逐步承接除 PC 以外的门店端访问。

- Admin 端继续使用现有 Next.js `/admin`，页面与操作方式保持不变。
- PC 门店端继续使用现有 Next.js `/store`。
- 新增 uni-app 门店端，目标覆盖 H5、微信小程序、Android 和 iOS。
- 新旧门店端迁移期间并行运行，共用现有数据库和门店业务 API。
- uni-app 全功能验收并稳定运行后，移动端入口统一切换到 uni-app。

## 2. 核心原则

1. 现网优先：开发过程不删除、不替换现有 `/store` 和 `/admin`。
2. 后端复用：继续使用现有 Next.js API 和 Prisma 数据层，不另建重复后端。
3. 向后兼容：PC/Admin 保持 Cookie 登录，uni-app 使用 Bearer Token。
4. 服务端定权：门店 ID 和权限只能从服务端登录会话取得，不能信任客户端参数。
5. 分批上线：每个模块单独开发、验收、灰度，不做一次性整体切换。
6. 随时回退：灰度期间保留旧移动 Web 入口，出现问题可立即恢复。

## 3. 技术方案

### 3.1 项目结构

```text
SYZHZS/
├─ nextjs-blog/          # 现有 Next.js：Admin、PC 门店端、API、数据库
└─ uniapp-store/         # 新增 uni-app：H5、小程序、App
```

uni-app 采用 Vue 3、TypeScript、Pinia。先使用 uni-app 官方跨端能力，不在首期引入重量级 UI 框架。

### 3.2 登录与会话

- 现有 PC/Admin：继续使用 `anyi_auth` HttpOnly Cookie。
- uni-app：新增移动端登录、刷新 Token、退出接口。
- `/api/store/*` 同时识别 Cookie 和 `Authorization: Bearer <token>`。
- Token 对应服务端会话，支持过期、刷新、主动退出和禁用账号失效。
- uni-app 不保存用户密码，只安全保存 Token 和必要的展示信息。

### 3.3 API 约定

- 继续复用 `/api/store/*`，不复制整套 `/api/mobile/*` 业务接口。
- 仅新增移动端认证相关接口。
- 保持现有请求和响应字段兼容，必要的新字段只能做可选扩展。
- 所有门店数据查询和写入都由服务端会话确定 `storeId`。
- 建立统一请求层，处理域名、Token、401 刷新、错误提示和超时。

### 3.4 跨端降级

- AI 对话：支持的平台使用流式输出，不支持的平台自动改为完整响应。
- PDF/PPT：使用下载后打开或受控 `web-view`，不移植浏览器 PDF.js DOM 操作。
- 打印：PC 保留浏览器打印；移动端提供 PDF、保存和分享。
- 剪贴板、文件、存储、全屏和外链统一使用 `uni.*` API。

## 4. 开发阶段

### 阶段 0：现网基线与保护（2～3 个工作日）

任务：

- 整理并提交当前已有改动，建立可回退基线标签。
- 记录当前部署环境、环境变量、数据库备份和恢复方式。
- 固化生产构建检查和核心功能冒烟清单。
- 建立 18 个门店页面、34 个门店 API 的迁移矩阵。
- 确认首批发布目标：H5、微信小程序、Android、iOS。

验收门槛：

- `npm run build` 通过。
- Admin 登录及核心管理功能正常。
- PC 门店登录、客户、报告、AI、学习中心核心链路正常。
- 数据库备份和恢复流程经过验证。

回退方式：使用基线版本和备份恢复，uni-app 尚未接入生产流量。

### 阶段 1：后端移动兼容层（4～7 个工作日）

任务：

- 增加移动端会话数据模型和认证接口。
- 抽取统一服务端会话解析，兼容 Cookie/Bearer Token。
- Middleware 同时支持两种认证方式。
- 审计全部 `/api/store/*`，服务端绑定 storeId 和权限。
- 配置 CORS、HTTPS、请求限流和小程序合法域名。
- 为登录、刷新、退出、越权访问建立自动化测试。

验收门槛：

- 现有 PC/Admin 登录方式和功能无变化。
- uni-app 测试请求可以使用 Token 访问门店 API。
- 修改请求中的 storeId 不能访问其他门店数据。
- Token 过期、退出、禁用账号后均不能继续访问。

回退方式：关闭移动端认证入口；Cookie 鉴权继续运行。

### 阶段 2：uni-app 基础工程（3～5 个工作日）

任务：

- 创建 `uniapp-store` Vue 3 + TypeScript 工程。
- 配置开发、测试、生产三套 API 环境。
- 建立 Pinia 登录状态、统一请求层和 Token 自动刷新。
- 建立页面权限守卫、TabBar、主题、空状态、错误页和网络重试。
- 接入登录、退出、个人资料和修改密码。

验收门槛：

- H5、微信开发者工具和 App 调试基座均可启动。
- 登录、自动续期、退出和权限菜单正确。
- 网络中断、401、超时均有明确提示且不会产生重复提交。

### 阶段 3：核心经营链路（8～12 个工作日）

迁移顺序：

1. 首页统计。
2. 客户列表、搜索、新增客户。
3. 身体记录、客户历史记录。
4. 报告提交和 AI 在线分析。
5. 报告查看、调理方案编辑与保存。
6. 移动端 PDF/分享能力。

验收门槛：

- 同一账号在 PC 和 uni-app 看到的数据一致。
- 新增、修改、删除操作都有成功反馈和防重复提交。
- 报告从创建到方案保存的完整链路通过。
- 权限不足的账号看不到入口，也不能直接调用接口。

### 阶段 4：AI 与内容功能（8～12 个工作日）

迁移顺序：

1. 月经助手会话和历史记录。
2. 问答查询。
3. 创作者身份。
4. 选题策划和选题库。
5. 内容创作。
6. 我的脚本库和公共脚本库。

验收门槛：

- AI 普通响应和流式降级均正常。
- 会话、选题和脚本数据不会跨门店。
- 复制、仿写、拍摄状态和统计功能与 PC 一致。
- AI 超时或供应商异常时不丢失用户已输入内容。

### 阶段 5：学习中心与平台适配（5～8 个工作日）

任务：

- 学习资源列表、分类和详情。
- Markdown 内容渲染。
- PDF/PPT 下载、打开和必要的 WebView 预览。
- 各平台安全区、键盘、导航栏和返回行为适配。
- 微信小程序域名、隐私协议和发布配置。
- Android/iOS 网络权限、应用图标和启动页配置。

验收门槛：

- 主要文件类型可查看或下载。
- 真机弱网、前后台切换、Token 过期场景通过。
- H5、微信小程序、Android、iOS 的核心路径表现一致。

### 阶段 6：全量回归与灰度切换（5～8 个工作日）

任务：

- 按迁移矩阵逐项对比 PC 与 uni-app。
- 使用测试门店进行第一轮灰度。
- 使用少量真实门店进行第二轮灰度。
- 监控登录失败率、接口错误率、AI 超时率和关键业务完成率。
- 灰度稳定后，将移动设备访问入口切换到 uni-app。
- PC `/store` 和 Admin `/admin` 保持不变。

切换门槛：

- P0/P1 缺陷为零。
- 核心业务回归通过率 100%。
- 连续 7 天无数据错乱、跨门店访问或无法登录问题。
- 已完成线上数据库备份和一键回退演练。

回退方式：恢复旧移动 Web 入口，不回滚业务数据；新旧端继续共用后端。

## 5. 功能迁移矩阵

| 模块 | PC 保留 | uni-app | 优先级 | 主要风险 |
| --- | --- | --- | --- | --- |
| 登录与权限 | 是 | 重写 | P0 | Cookie、Token、权限同步 |
| 首页统计 | 是 | 重写 | P0 | 数据范围 |
| 客户管理 | 是 | 重写 | P0 | 跨门店隔离、长表单 |
| 报告与在线分析 | 是 | 重写 | P0 | 草稿、AI 超时、移动表单 |
| 调理方案 | 是 | 重写 | P0 | 打印、PDF、编辑状态 |
| 月经助手 | 是 | 重写 | P1 | 流式响应、会话一致性 |
| 问答查询 | 是 | 重写 | P1 | 搜索耗时、结果一致性 |
| 短视频创作 | 是 | 重写 | P1 | 长文本、复制、草稿 |
| 学习中心 | 是 | 重写 | P1 | PDF/PPT、WebView 域名 |
| 个人资料 | 是 | 重写 | P0 | 密码修改、退出登录 |
| Admin | 是 | 不开发 uni-app | P0 | 必须保持现状 |

## 6. 测试清单

- 角色：Admin 代看门店、门店主账号、不同权限门店子账号。
- 数据：空数据、单条、大量分页、特殊字符、长文本。
- 安全：未登录、过期 Token、伪造 storeId、越权资源 ID、重复提交。
- 网络：弱网、断网、接口超时、AI 中断、应用切后台后恢复。
- 平台：PC Chrome、移动 H5、微信真机、Android 真机、iOS 真机。
- 回归：Admin 和 PC 门店端每个阶段至少执行一次冒烟测试。

## 9. 完成定义

只有同时满足以下条件，才视为迁移完成：

- uni-app 覆盖现有门店端全部有效业务功能。
- PC 门店端和 Admin 没有功能回退。
- 门店数据隔离、权限、登录安全通过测试。
- H5、微信小程序、Android、iOS 真机验收通过。
- 灰度期达到切换门槛并完成回退演练。
- 移动端入口已经统一切换到 uni-app，PC `/store` 继续保留。
